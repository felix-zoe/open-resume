## 1. 全局设计规范与约定

### 1.1 服务与基础路径
- **生产环境 Base URL**：`https://api.yourdomain.com/api` 或 `/api` (Cloudflare Pages Functions 同域反代)
- **本地开发 Base URL**：`http://127.0.0.1:8787/api` (Wrangler 本地模拟器)
- **协议**：统一采用 `HTTPS`，字符集 `UTF-8`。
- **数据格式**：请求和响应的 Content-Type 默认均为 `application/json; charset=utf-8`（文件上传接口除外，为 `multipart/form-data`）。

### 1.2 认证与权限传递
- 采用 **JWT (JSON Web Token)** 无状态认证机制。
- 登录成功后，客户端需在所有受保护接口的 HTTP 请求头中附带：
  ```http
  Authorization: Bearer <your_jwt_token>
  ```
- 若未提供 Token 或 Token 过期失效，统一返回 HTTP 状态码 `401 Unauthorized`。

### 1.2.1 CORS 与频率限制
- **CORS 白名单**：只放行环境变量 `APP_ORIGIN` 中列出的来源（逗号分隔，如 `http://localhost:5173`）。
  未配置时**不放行任何跨域来源**；同源请求不受影响（不带 `Origin` 头即不加 CORS 响应头）。
  允许的方法：`GET, POST, PUT, PATCH, DELETE, OPTIONS`；允许的请求头：`Authorization, Content-Type`。
- **频率限制**（固定窗口，按 IP 计数，超限返回 `42901` + `Retry-After`）：

  | 接口 | 阈值 |
  | :--- | :--- |
  | `POST /api/auth/login` | 10 次 / 分钟 / IP |
  | `POST /api/auth/register` | 5 次 / 小时 / IP |
  | `POST /api/share/:id/visit`、`POST /api/s/:token/visit` | 60 次 / 分钟 / IP |
  | `POST /api/s/:token/unlock` | 10 次 / 分钟 / IP |
  | `POST /api/auth/password` | 10 次 / 分钟 / IP（与登录同档） |
  | `POST /api/telemetry` | 120 次 / 分钟 / IP |
  | `POST /api/ai/rewrite`、`POST /api/ai/models` | 30 次 / 分钟 / IP（共用一档计数） |

- **账号字段规范**：邮箱入库前统一 `trim().toLowerCase()`，长度 ≤ 254；密码 6–128 位；
  昵称留空时取邮箱前缀，最长 20 字符。

- **响应头**：所有 `/api/**` 响应带 `X-Request-Id`（12 位十六进制风格的随机串），
  用于把客户端报错与服务端日志对上；客户端可自带该头，服务端会沿用。

### 1.3 统一响应数据结构 (`ApiResponse<T>`)
所有接口返回格式均保持如下统一结构：

#### 成功响应格式
```json
{
  "code": 0,
  "message": "success",
  "data": { ... }
}
```

#### 失败响应格式
```json
{
  "code": 40001,
  "message": "邮箱格式不正确",
  "data": null
}
```

### 1.4 全局业务状态码表 (Error Codes)
| 业务码 (`code`) | HTTP 状态码 | 说明 (Description) |
| :--- | :--- | :--- |
| `0` | 200 | 操作成功 (Success) |
| `40000` | 400 | 通用客户端请求参数错误 |
| `40001` | 400 | 邮箱或密码格式不合法 |
| `40002` | 400 | 用户已存在，无法重复注册 |
| `40003` | 400 | 上传文件格式或体积超出限制（仅限图片且 ≤ 2MB） |
| `40004` | 400 | 头像文件体积超过 2MB（上传头像时给出更具体的提示） |
| `40005` | 400 | 头像格式不支持（仅限 JPG / PNG / WebP） |
| `40101` | 401 | 缺少认证 Token 或签名无效 |
| `40102` | 401 | Token 已过期，请重新登录 |
| `40103` | 401 | 账号或密码错误 |
| `40104` | 401 | 修改密码时提供的当前密码不正确 |
| `40105` | 401 | 账号已按注销申请完成删除（登录时触发） |
| `40301` | 403 | 无权限操作该简历资源（非当前所有者） |
| `40006` | 400 | 内容与最近一个版本相同，无需重复保存 |
| `40007` | 400 | 投递记录引用的简历不存在或不属于当前用户 |
| `40008` | 400 | AI 改写：厂商 / 模型 / 风格 / 原文不合法或超出长度上限 |
| `40009` | 400 | AI 改写：未填写 API Key，或 Key 长度异常 |
| `40010` | 400 | AI 改写：接口地址不被允许（非 https、指向内网、带凭证等） |
| `40401` | 404 | 请求的资源（简历/投递记录/文件/用户）不存在 |
| `41001` | 410 | 分享链接已撤销或已过期 |
| `42901` | 429 | 触发频率限制（响应头 `Retry-After` 给出等待秒数） |
| `50001` | 500 | 边缘服务或数据库内部执行错误 |
| `50002` | 500 | R2 对象存储未开通（上传头像时返回，提示改用本地图片） |
| `50003` | 500 | 服务端未配置 `JWT_SECRET` |
| `50201` | 502 | AI 上游：API Key 无效或无权调用该模型 |
| `50202` | 502 | AI 上游：接口地址或模型名不存在 |
| `50203` | 502 | AI 上游：服务商限流或账户余额不足 |
| `50204` | 502 | AI 上游：服务商拒绝了本次请求（参数/用法不被支持） |
| `50205` | 502 | AI 上游：其他非 2xx 响应（含具体状态码） |
| `50206` | 504 | AI 上游：连接失败或超时（服务端 45 秒中止） |
| `50207` | 502 | AI 上游：接口地址返回了 3xx 跳转，不予跟随 |
| `50208` | 502 | AI 上游：返回内容无法解析或为空 |
| `50209` | 502 | AI 上游：返回内容超过 6000 字，已丢弃 |

> `40002` 在注册场景表示「邮箱已注册」，在简历保存场景表示「体积超限」——
> 两者都是「请求本身合法但被拒绝」，靠 HTTP 状态（400 / 413）与 message 区分。

> `502xx` 全部由 `/api/ai/*` 产生，语义是「**用户自己配置的模型服务商**没配合」，
> 而非本站故障。因此它们**刻意不使用 401**（`src/utils/http.ts` 把 401 当作登录态失效，
> 会触发登出跳转，而「API Key 填错」与账号无关），也**不计入 `server.error.*` 告警**
> （否则一个填错 Key 的用户就能让「5xx > 20 次/天」的阈值响一整晚）。

## 2. 接口详细规格说明

### 2.1 用户认证模块 (Authentication)

#### 2.1.1 用户注册
- **接口功能**：创建新用户账号并初始化默认简历骨架。
- **请求方法**：`POST`
- **请求路径**：`/api/auth/register`
- **权限要求**：公开免鉴权

**请求 Body (JSON)**：
| 参数名 | 类型 | 必填 | 限制说明 | 示例值 |
| :--- | :--- | :--- | :--- | :--- |
| `email` | string | 是 | 有效邮箱格式，长度 ≤ 64 | `xiaofan@example.com` |
| `password` | string | 是 | 6~32 位字符 | `Pass123456` |
| `nickname` | string | 否 | 长度 ≤ 20，默认取邮箱前缀 | `张小凡` |

**响应 Data 结构**：
```json
{
  "code": 0,
  "message": "注册成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "user": {
      "id": "usr_9b1deb4d3b7d4e12",
      "email": "xiaofan@example.com",
      "nickname": "张小凡",
      "avatarUrl": ""
    }
  }
}
```

**请求 Body (JSON)**：

#### 2.1.3 获取当前登录用户信息
- **接口功能**：用于前端初始化鉴权状态，维持登录态。
- **请求方法**：`GET`
- **请求路径**：`/api/auth/me`
- **权限要求**：需携带 Bearer Token

**响应 Data 结构**：
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "id": "usr_9b1deb4d3b7d4e12",
    "email": "xiaofan@example.com",
    "nickname": "张小凡",
    "avatarUrl": "https://r2.yourdomain.com/avatars/avatar_123.webp",
```

`deletionRequestedAt` / `deletionDaysLeft` 用于账号设置页展示「注销冷静期还剩 N 天」；
未申请注销时两者均为 `null`。

- **权限要求**：需携带 Bearer Token

**请求 Body (JSON)**：
| 参数名 | 类型 | 必填 | 示例值 |
| :--- | :--- | :--- | :--- |

#### 2.1.5 修改密码
- **接口功能**：用当前密码换新密码。
- **请求方法**：`POST`
- **请求路径**：`/api/auth/password`
- **权限要求**：需携带 Bearer Token；**同时需要正确的当前密码**
- **频率限制**：与登录共用 10 次 / 分钟 / IP

> 必须校验当前密码：只有 JWT 就能改密码，等于把「token 泄露」升级成「永久接管账号」。
> 改密后旧 token 仍有效（JWT 无状态），这是刻意取舍——见执行状态文档 T5.5 偏差 3。

**请求 Body (JSON)**：
| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `currentPassword` | string | 是 | 当前密码 |
| `newPassword` | string | 是 | 6–128 位，且不能与当前密码相同 |

**失败响应**：
| 场景 | code | HTTP |
| :--- | :--- | :--- |
| 当前密码错误 | `40104` | 401 |
| 新密码不合规 / 与当前相同 | `40001` | 400 |

**成功响应**：`{ "code": 0, "message": "密码已更新", "data": null }`

---

#### 2.1.6 导出账号数据
- **接口功能**：把用户自己的全部内容打包成一份 JSON。
- **请求方法**：`GET`
- **请求路径**：`/api/auth/export`
- **权限要求**：需携带 Bearer Token
- **响应头**：`Content-Disposition: attachment; filename="openresume-<email>-<YYYY-MM-DD>.json"`

**包含**：简历正文与主题、版本历史、分享链接（不含密码哈希）、投递记录、账号基本信息。

**不包含**：
- `password_hash`（只会增加泄露面）；
- 访问统计（那是访客的行为数据，不是用户自己的内容）。

**响应 Data 结构**：
```json
{
  "format": "openresume-account-export",
  "version": 1,
  "exportedAt": 1760000000,
  "account": { "id": "usr_...", "email": "a@example.com", "nickname": "阿离", "createdAt": 1727400000 },
  "counts": { "resumes": 3, "versions": 12, "shareLinks": 2, "applications": 5 },
  "resumes": [],
  "versions": [],
  "shareLinks": [],
  "applications": []
}
```

> 前端不能用 `<a href>` 直接下载：那条路径不带 `Authorization` 头，浏览器会拿到 401 存成一个「失败页面」文件。必须 `fetch` 后构造 Blob。

---

#### 2.1.7 申请注销账号（7 天冷静期）
- **接口功能**：把账号标记为「待删除」，7 天后执行真正的删除。
- **请求方法**：`POST`
- **请求路径**：`/api/auth/deletion`
- **权限要求**：需携带 Bearer Token

**请求 Body (JSON)**：
| 参数名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `email` | string | 是 | 必须与账号邮箱一致（忽略大小写），用于二次确认 |

**成功响应**：
```json
{
  "code": 0,
  "message": "注销申请已提交，7 天内登录可撤销",
  "data": { "deletionRequestedAt": 1760000000, "deletionDaysLeft": 7 }
}
```

**生命周期语义**：
1. 提交后写入 `users.deletion_requested_at`，账号仍可正常使用；
2. **冷静期内登录即自动撤销**（清空该列）——能登进来说明用户后悔了，不该再让他去找撤销入口；
3. 到期后：登录时惰性删除（返回 `40105`），或由 `npm run db:purge:remote` 定时清理；
4. 删除范围：简历、版本历史、分享链接、投递记录、访问记录、用户行。R2 头像由清理脚本处理。

---

#### 2.1.8 撤销注销
- **接口功能**：取消待执行的注销。
- **请求方法**：`DELETE`
- **请求路径**：`/api/auth/deletion`
- **权限要求**：需携带 Bearer Token
- **成功响应**：`{ "code": 0, "message": "已撤销注销申请，账号恢复使用", "data": null }`

### 2.2 简历管理与内容持久化模块 (Resume Management)

#### 2.2.1 获取我的简历列表
- **接口功能**：获取当前用户拥有的所有简历元数据列表（精简模式，不传输庞大的 content，极大提升加载速度并节约 D1 读配额）。服务端在查询时顺带算出 `completeness`，避免前端为每张卡片各发一次详情请求。
- **请求方法**：`GET`
- **请求路径**：`/api/resumes`
- **权限要求**：需携带 Bearer Token

**响应 Data 结构**：
```json
{
  "code": 0,
  "message": "success",
  "data": [
    {
      "id": "res_8f7b2c9d1a3e",
      "title": "前端技术专家-张小凡",
      "templateId": "classic",
      "isPublic": 0,
      "createdAt": 1727401200,
      "updatedAt": 1727415600,
      "completeness": { "score": 90, "missing": ["metric"] }
    },
    {
      "id": "res_0a1b2c3d4e5f",
      "title": "应届生求职-张小凡",
      "templateId": "geek",
      "isPublic": 1,
      "createdAt": 1727300000,
      "updatedAt": 1727310000,
      "completeness": { "score": 100, "missing": [] }
    }
  ]
}
```

**`completeness` 字段说明**：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `score` | number | 0–100 整数。按「招聘方一定会看的信息」加权求和，**不判断内容质量** |
| `missing` | string[] | 未通过的检查项 key，按权重降序，前端映射成中文提示 |

检查项与权重（见 `functions/lib/completeness.ts`）：

| key | 权重 | 判定 |
| :--- | :--- | :--- |
| `name` | 15 | `profile.name` 非空 |
| `jobTitle` | 10 | `profile.title` 非空 |
| `contact` | 15 | `profile.email` 或 `profile.phone` 任一非空 |
| `summary` | 10 | `profile.summary` 非空 |
| `experience` | 20 | 可见的 `work` 或 `projects` 至少一条 |
| `education` | 10 | 可见的 `education` 至少一条 |
| `skills` | 10 | 可见的 `skills` 至少一条 |
| `metric` | 10 | 经历描述里出现数字 |

> 注意：`visible: false` 的模块不计入（看不见的内容不该算「完整」）。结构异常时按未通过处理，宁低不高。

### 2.3B token 化分享链接（v2.0 新增）

简历 id 会出现在编辑器地址栏与工作台，天然可枚举，无法承担「私密投递」语义。v2.0 改为**随机 token + 可撤销 + 可设密码/有效期/脱敏**。

#### 2.3B.1 列出生效中的分享链接
- **请求方法**：`GET`
- **请求路径**：`/api/resumes/:id/share-links`
- **权限要求**：需携带 Bearer Token（仅简历所有者）

**响应 Data**：数组，每项含 `id`、`token`、`url`（`/s/:token`）、`label`、`expiresAt`（`null` = 永久）、`allowDownload`、`maskContact`、`hasPassword`、`revokedAt`、`viewCount`、`lastViewedAt`、`createdAt`、`status`（`ok` / `revoked` / `expired` / `needs-password`）。

#### 2.3B.2 创建分享链接
- **请求方法**：`POST`
- **请求路径**：`/api/resumes/:id/share-links`
- **权限要求**：需携带 Bearer Token

**请求 Body**：
| 参数名 | 类型 | 必填 | 说明 | 默认 |
| :--- | :--- | :--- | :--- | :--- |
| `ttl` | string | 否 | `7d` / `30d` / `permanent` | `30d` |
| `password` | string | 否 | 访问密码，4–64 字符，PBKDF2 存储 | 无 |
| `maskContact` | boolean | 否 | 隐藏完整手机号/邮箱 | `true` |
| `allowDownload` | boolean | 否 | 允许访客打印为 PDF | `true` |
| `label` | string | 否 | 备注名，≤50 字符 | 空 |

**响应 Data**：`{ id, token, url, hasPassword, allowDownload, maskContact, expiresAt, createdAt }`

#### 2.3B.3 撤销分享链接
- **请求方法**：`DELETE`
- **请求路径**：`/api/share-links/:id`
- **权限要求**：需携带 Bearer Token（仅创建者）
- **说明**：软删除（写 `revoked_at`），记录保留便于审计。

#### 2.3B.4 通过 token 读取分享简历
- **请求方法**：`GET`
- **请求路径**：`/api/s/:token`
- **权限要求**：公开免鉴权

**行为**：
- 链接不存在 / 已撤销 → `404`（40401）；已过期 → `410`（41001）；
- 需要密码 → `200` + `{ requiresPassword: true, title }`（**不返回内容**）；
- 正常 → `{ requiresPassword: false, id, title, templateId, content, themeConfig, allowDownload, maskContact, updatedAt }`；
- `maskContact = true` 时，服务端把 `profile.phone` 脱敏为 `138****8000`、`profile.email` 脱敏为 `z***@example.com`。

#### 2.3B.5 提交访问密码
- **请求方法**：`POST`
- **请求路径**：`/api/s/:token/unlock`
- **请求 Body**：`{ password: string }`
- **响应**：同 2.3B.4 的正常分支；密码错误返回 `401`（40102）。
- **注意**：`/api/s/*` 的 401 **不会**触发前端全局登出（访客本就未登录）。

#### 2.3B.6 上报 token 分享访问
- **请求方法**：`POST`
- **请求路径**：`/api/s/:token/visit`
- **请求 Body**：`{ duration?: number, isDownloaded?: boolean }`
- **响应**：`{ counted: boolean, reason: 'bot' | 'duplicate' | null, visitId }`

#### 2.7.1 投递记录列表与汇总
- **请求方法**：`GET`
- **请求路径**：`/api/jobs`

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [
      {
        "id": "job_9f2c1a7b3d4e5f60",
        "resumeId": "res_8f7b2c9d1a3e",
        "resumeTitle": "前端工程师 - 2026",
        "company": "某互联网公司",
        "position": "高级前端工程师",
        "location": "北京",

        "status": "interviewing",
        "appliedAt": 1760000000,
        "nextActionAt": 1760600000,
        "nextActionNote": "等二面通知",
        "salaryRange": "25-35K",
        "jobUrl": "https://example.com/jobs/123",
        "notes": null,

      "dueSoon": 2
    }
  }

```

- `resumeTitle` 由 `LEFT JOIN resumes` 带出；简历被删除后 `resumeId` 与 `resumeTitle` 均为 `null`（`ON DELETE SET NULL`）。
- 列表按 `updated_at DESC` 排序。

**统计口径**（`functions/lib/applications.ts` 的 `computeApplicationStats`，前端不重复计算）：

| 字段 | 含义 |
| :--- | :--- |
| `total` | 全部记录数（含「想投」） |
| `applied` | 已投递，即 `applied / interviewing / offer / rejected` 四态之和，**不含 `saved`** |
| `interviewRate` | `(interviewing + offer) / applied`，四舍五入到整数百分比 |
| `offerRate` | `offer / applied`，四舍五入到整数百分比 |
| `dueSoon` | `nextActionAt` 在 7 天内（含已逾期）且状态不是 `offer`/`rejected` 的记录数 |

分母为 0 时两个比率都返回 `0` 而不是 `NaN`——`NaN` 会一路传到界面显示成 `NaN%`。

#### 2.7.2 新增投递记录
- **请求方法**：`POST`
- **请求路径**：`/api/jobs`
- **权限要求**：需携带 Bearer Token

**请求 Body**：
| 字段名 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `company` | string | 是 | 公司名称，去空白后不能为空 |
| `position` | string | 是 | 岗位名称，去空白后不能为空 |
| `status` | enum | 否 | `saved`/`applied`/`interviewing`/`offer`/`rejected`，默认 `applied` |
| `resumeId` | string \| null | 否 | 关联简历；必须属于当前用户，否则返回 `40007` |
| `appliedAt` | number \| null | 否 | 投递日期（秒）；`status` 为 `applied` 且未传时由服务端补当前时间 |
| `location` / `channel` / `nextActionAt` / `nextActionNote` / `salaryRange` / `jobUrl` / `notes` | — | 否 | 见 2.7.1 字段表 |

**响应 Data 结构**：`{ "id": "job_9f2c1a7b3d4e5f60", "createdAt": 1760000000 }`

#### 2.7.3 更新投递记录
- **请求方法**：`PATCH`
- **请求路径**：`/api/jobs/:id`
- **权限要求**：需携带 Bearer Token（仅记录所有者）

Body 为 2.7.2 字段的任意子集。语义是「只改出现的字段」——**未出现的字段保持原值**，不会被写成 `null`；
字符串字段传空串会统一存为 `NULL`（避免「有值但是空」的两种状态）。一个字段都没传返回 `40001`。

**响应 Data 结构**：`{ "id": "job_...", "updatedAt": 1760100000 }`

#### 2.7.4 删除投递记录
- **请求方法**：`DELETE`
- **请求路径**：`/api/jobs/:id`
- **权限要求**：需携带 Bearer Token（仅记录所有者）

**响应 Data 结构**：`{ "id": "job_..." }`

### 2.8 可观测性上报模块 (Telemetry)

#### 2.8.1 上报前端事件

- **接口功能**：接收前端的错误、Web Vitals 与业务埋点，按天聚合计数。
- **请求方法**：`POST`
- **请求路径**：`/api/telemetry`
- **权限要求**：公开（未登录用户的报错同样有价值）
- **频率限制**：120 次/分/IP
- **成功响应**：`204 No Content`（无响应体）

**请求 Body (JSON)**：
```json
{
  "events": [
    { "kind": "event", "name": "page.Editor", "path": "/editor/:id" },
    { "kind": "vital", "name": "lcp", "value": 1234.5, "path": "/" },
    { "kind": "error", "name": "window.error", "path": "/dashboard" }
  ]
}
```

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `events[].kind` | `error` \| `vital` \| `event` | 事件类别；其他值直接丢弃 |
| `events[].name` | string | 事件名，须匹配 `^[a-zA-Z][a-zA-Z0-9._:-]*$`，≤ 64 字符 |
| `events[].value` | number | 仅 `vital` 使用；须为 0–600000 的有限数 |
| `events[].path` | string | 归一化路径（`/editor/:id`）；服务端会再归一化一次 |
| `events[].message` | string | 仅错误使用；**不入聚合表**，只进结构化日志 |

**服务端行为**：
1. 单批最多处理 50 条，其余丢弃；
2. 按 `(day, kind, name, path)` 聚合后 `INSERT … ON CONFLICT DO UPDATE` 累加，天然幂等；
3. **任何参数问题都不返回 4xx**——埋点客户端不该处理错误分支，非法事件直接丢弃，始终 204；
4. 写入失败只打 `warn` 日志，绝不影响业务响应。

**为什么不做鉴权**：首页白屏比登录后保存失败更严重，而未登录用户没有 token。
代价是任何人都能往聚合表里加计数，用「限流 + 事件名白名单 + 路径归一化」把损失压到「多几个数字」。

**为什么不存原始事件**：D1 免费额度每天 10 万次写入，单条事件表很快就写满；
聚合表里没有 `user_id` / IP / 原始路径，即使泄露也不构成个人数据。

#### 2.8.2 结构化日志与请求 ID

所有 `/api/**` 响应都带 `X-Request-Id`（客户端可自带，服务端沿用）。每个请求在完成后输出一行 JSON：

```json
{"level":"info","ts":1760000000,"requestId":"a1b2c3d4e5f6","method":"PUT","path":"/api/resumes/:id","status":200,"ms":42}
```

| 字段 | 说明 |
| :--- | :--- |
| `level` | `info` / `warn`（4xx）/ `error`（5xx 或抛异常）；`/api/ai/*` 的 5xx 记 `warn`，理由见 §2.9 |
| `requestId` | 12 位随机串，用来把一次请求的所有日志行串起来 |
| `path` | 已归一化（`res_xxx` → `:id`），避免日志基数爆炸 |
| `ms` | 处理耗时 |

**日志里不记请求体与查询串**：简历正文、分享密码都在里面。

#### 2.8.3 服务端事件与告警口径

服务端自己记的事件（客户端不参与）：

| 事件名 | 触发时机 |
| :--- | :--- |
| `auth.login.fail` | 登录失败（用户不存在或密码错误），不记是谁 |
| `auth.register.ok` | 注册成功 |
| `ai.rewrite.ok` | AI 改写成功一次（不记模型名与内容，那是用户的隐私） |
| `ai.rewrite.fail` | AI 改写失败一次（含参数错误与上游错误）——接入失败率是「预设地址/模型名是否已过期」的唯一信号 |
| `server.error.5xx` | 任意接口返回 5xx（`kind = server`）；**`/api/ai/*` 除外**，见 §2.9 |

`npm run check:alerts` 读 `telemetry_daily` 判定三条阈值：

| 指标 | 计算 | 阈值 |
| :--- | :--- | :--- |
| 导出失败率 | `export.*.fail / (export.*.ok + export.*.fail)` | > 5% |
| 登录失败率 | `auth.login.fail / (auth.login.fail + auth.login.ok)` | > 40% |
| 服务端 5xx | `server.error.5xx` 绝对次数 | > 20 次/天 |

分母 < 10 时不判定（避免「2 次请求失败 1 次 = 50%」）。脚本退出码非 0 即超阈值，
`.github/workflows/alerts.yml` 每天 UTC 01:10 跑一次。

### 2.9 AI 改写模块 (AI Rewrite)

> **这两个接口不需要登录**：模型调用用的是**用户自己的 API Key**，成本由他承担，
> 游客也能用。因此请求头**不带 `Authorization`**——带上只会让「Key 错了」和
> 「登录过期了」两件不相干的事在错误分支里混在一起。

#### 2.9.1 改写一段文字

- **接口功能**：把用户选中的**某一段**简历文字按指定风格改写，返回候选文本（**不落库**）。
- **请求方法**：`POST`
- **请求路径**：`/api/ai/rewrite`
- **权限要求**：公开（无需登录）
- **频率限制**：30 次/分/IP（与 `/api/ai/models` 共用一档）

**请求 Body (JSON)**：
```json
{
  "providerId": "deepseek",
  "baseUrl": "",
  "model": "deepseek-chat",
  "apiKey": "sk-xxxxxxxx",
  "text": "负责公司官网前端开发工作",
  "style": "professional",
  "target": "work",
  "instruction": "突出技术选型",
  "context": "招聘要求：Vue3 + TypeScript，3 年以上"
}
```

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `providerId` | string | 是 | 厂商 id，取值见 §2.9.4；不在表内返回 `40008` |
| `baseUrl` | string | 仅自定义厂商 | **预设厂商传空即可**，服务端以 `shared/ai.ts` 的白名单地址为准并完全忽略此字段；`custom` 时必填且须为合规 https 地址 |
| `model` | string | 是 | 模型名，≤ 120 字符。火山方舟要填接入点 ID（`ep-xxxx`） |
| `apiKey` | string | 是 | 用户自己的 Key，≤ 400 字符。**仅存在于本次请求的内存中** |
| `text` | string | 是 | 待改写的原文，≤ 2000 字符（`AI_LIMITS.maxInputChars`） |
| `style` | string | 是 | 改写风格，取值见 §2.9.4 |
| `target` | string | 否 | 段落类型：`summary` / `work` / `project` / `skills` / `custom`（默认 `custom`），决定提示词里的身份说明 |
| `instruction` | string | 否 | 用户补充要求，≤ 300 字符 |
| `context` | string | 否 | 目标岗位背景（JD 摘要），≤ 600 字符；明确告知模型「不得引入原文没有的经历」 |

**成功响应**：`200 OK`
```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "text": "主导公司官网前端研发，基于 Vue3 + TypeScript 完成组件库沉淀",
    "inputChars": 15,
    "outputChars": 32
  }
}
```

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `data.text` | string | 已清洗的改写结果：剥掉了 ```` ``` ```` 围栏与「改写后的内容：」这类引导语，连续空行已压缩 |
| `data.inputChars` | number | 原文长度，供前端展示字数变化 |
| `data.outputChars` | number | 结果长度 |

**失败响应**：`400`（`40008` / `40009` / `40010`）、`429`（`42901`）、`502`（`50201`–`50205`、`50207`–`50209`）、`504`（`50206`）。
`502xx` 的 message 会附上**服务商原话**（截断 200 字），形如：
```json
{
  "code": 50201,
  "message": "API Key 无效，或没有该模型的调用权限（服务商返回：Authentication Fails, Your api key: ****0000 is invalid）",
  "data": null
}
```

**服务端行为**：
1. 限流 → 参数校验 → 拼提示词 → `POST {baseUrl}/chat/completions`（`temperature: 0.3`、`max_tokens: 1200`、`stream: false`）；
2. `redirect: 'manual'`，3xx 一律判失败（`50207`）——否则自定义地址可先用公网域名 302 到内网地址绕过校验；
3. `AbortSignal.timeout(45_000)`；客户端超时给到 60 秒，**必须大于服务端**，否则先超时的是浏览器，翻译好的错误文案永远送不到用户眼前；
4. 返回内容按 `data.maxOutputChars = 6000` 截断判定，超长视为异常而非「写得好」；
5. 成功记 `ai.rewrite.ok`、失败记 `ai.rewrite.fail`；成功时输出一行结构化日志 `{"event":"ai.rewrite","provider":…,"style":…,"target":…,"inputChars":…,"outputChars":…}`。

#### 2.9.2 拉取厂商模型列表

- **接口功能**：从用户配置的厂商拉一份实时模型清单，供界面提示。厂商改名频繁（`glm-4-plus` → `glm-5`），预设里的名字半年就会过期，有了它用户不必等我们更新代码。
- **请求方法**：`POST`
- **请求路径**：`/api/ai/models`
- **权限要求**：公开（无需登录）
- **频率限制**：30 次/分/IP（与 `/api/ai/rewrite` 共用一档）

**请求 Body (JSON)**：
```json
{ "providerId": "zhipu", "baseUrl": "", "apiKey": "xxxxx" }
```

**成功响应**：`200 OK`
```json
{ "code": 0, "message": "ok", "data": { "models": ["glm-4-air", "glm-4-flash", "glm-4-plus"] } }
```

**服务端行为**：`GET {baseUrl}/models`（超时 20 秒）；兼容 `data[]` 与 `models[]` 两种返回形态；去重后按字典序排序并截断 200 条。
不支持 `/models` 的厂商会返回 `50202`（404 被翻译为「接口地址或模型名不存在」），
前端**只当提示不当错误**——手填模型名一直是可用的。

#### 2.9.3 隐私与安全边界

| 边界 | 实现 |
| :--- | :--- |
| API Key 不落库 | 只作为 `callChatCompletion()` 的入参存在于一次请求的内存中；不写 D1、不写 KV、不进日志 |
| 原文不落库 | 请求体不进结构化日志（日志只记 `method/path/status/ms` 与字数区间），改写结果只回给前端由用户决定是否采纳 |
| 不记 model 名 | `ai.rewrite.ok` 埋点与日志只带 `providerId`（预设 id），不带用户手填的模型名 |
| 只送选中的那一段 | 上限 2000 字，前端始终只取当前编辑的那一段，不整份简历上报 |
| SSRF 防护 | 预设厂商走白名单；自定义仅允许 https、禁止带凭证/查询串/锚点、拦截 `127.` `10.` `172.16–31.` `192.168.` `169.254.` `::1` `fc00::/7` `*.local` `*.internal` 等私有与保留地址 |
| 不做 401 | 见 §1.4 说明；「Key 填错」不该升级成「被动登出」 |
| 不计入 5xx 告警 | `/api/ai/*` 的 502/504 是上游问题，日志记 `warn` 且不写 `server.error.*` |
| 限流 | 30 次/分/IP。成本由用户的 Key 承担，这一档挡的是「本站被当成可自由转发的代理」 |

#### 2.9.4 厂商预设与风格枚举

唯一来源为 `shared/ai.ts`（前端与 Worker 共用），前端**不得**在任何组件中硬编码厂商域名——
`scripts/check-static.mjs` 的 `ai-base-url-source` 规则会把 12 个厂商域名从 `src/` 中拦下。

**厂商（`AI_PROVIDERS`，均走 OpenAI 兼容协议）**：`deepseek`、`dashscope`（阿里云百炼）、`zhipu`、`moonshot`、`ark`（火山方舟，模型填接入点 ID）、`qianfan`（百度千帆）、`hunyuan`（腾讯混元）、`spark`（讯飞星火）、`siliconflow`、`minimax`、`stepfun`、`baichuan`，以及 `custom`（任意 OpenAI 兼容端点：自建网关、One-API、vLLM 等）。

**风格（`AI_REWRITE_STYLES`）**：`polish` 润色通顺、`concise` 精简压缩、`quantify` 突出成果、`star` STAR 结构、`professional` 专业措辞、`fix` 纠错校对、`translate-en` 译成英文。

**提示词刻意不放在 `shared/ai.ts`**：它是服务端实现细节，前端既不需要知道，也不该让它随构建产物发出去。

## 4. 后端路由实现架构示例 (Hono on Cloudflare Workers)

基于 Hono 框架的路由器组织结构清晰简洁：

```typescript
import { Hono } from 'hono';

type Bindings = {
  DB: D1Database;
  BUCKET?: R2Bucket;
  JWT_SECRET: string;
  /** 前端站点 Origin，用于 CORS 白名单；未配置时回退为同源 */
  APP_ORIGIN?: string;
};

const app = new Hono<{ Bindings: Bindings }>();

// 1. 全局中间件：手写 CORS 白名单
//    不用 hono/cors()，因为它默认 `origin: '*'`，会把 Authorization 暴露给任意站点。
app.use('*', async (c, next) => {
  const origin = resolveAllowedOrigin(c.req.header('Origin'), c.env.APP_ORIGIN);
  if (c.req.method === 'OPTIONS') {
    return c.body(null, 204, corsHeaders(origin));
  }
  await next();
  for (const [key, value] of Object.entries(corsHeaders(origin))) {
    c.res.headers.set(key, value);
  }
});

// 2. 鉴权：需要登录的路由各自调用 requireAuth(c)，而不是按路径前缀挂中间件
//    （`/api/resumes/:id` 的 GET 在简历公开时允许匿名访问，前缀中间件会误拦）

// 3. 路由全部集中在 functions/api/[[route]].ts，按模块用注释分节：
//    Auth → Resumes → Upload → Share → Versions → Analytics → Jobs → AI

export default app;
```

**相关模块**：

| 文件 | 职责 |
| :--- | :--- |
| `functions/api/[[route]].ts` | 全部 REST 路由 |
| `functions/_middleware.ts` | 安全响应头（CSP/XCTO/Referrer-Policy/XFO/Permissions-Policy）+ 分享页 OG 注入 |
| `functions/lib/security.ts` | JWT 签发/校验、PBKDF2 哈希、`requireJwtSecret()` |
| `functions/lib/rate-limit.ts` | D1 固定窗口限流 |
| `functions/lib/schemas.ts` | zod 请求体校验 |
