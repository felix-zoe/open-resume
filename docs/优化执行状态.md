### 1.2 一句话判断

**原方案 M0–M5 的全部任务已落地，包含可选的 AI 改写（T5.7）；剩余只有明确记录为不做的「应用界面多语言」与两项需要人工过一眼的验收。**

产品已从「功能演示态」推进到「可交付产品态」：真分页预览与打印一致、字号与主题真实生效、游客与登录都不丢内容、分享链接可设密码/有效期/脱敏、导出覆盖 PDF/Word/Markdown/JSON、导入支持 JSON/文本/Markdown、注册有合规勾选、工作台能按模板缩略图与完整度管理多份简历、登录前不会替用户擅自上传草稿、投递记录能按状态看板管理并算出面试率与 Offer 率、同一份简历可以中英双语渲染并按语言导出、六个岗位示例页带结构化数据且服务端 head 正确、装上即可离线编辑并断网打开。账号也能自己改密码、导出全部数据、申请注销并留 7 天反悔期；线上出了问题，错误、性能与关键业务量都有数据可查，且有阈值告警兜底。AI 改写则用「用户自带 Key + 12 家国内主流厂商预设 + 自定义端点」的方式落地：结果先出 diff、点「采纳」才写回，Key 与正文不落库不写日志，服务端另加 SSRF 白名单与 30 次/分限流。至此方案 M5 收官，剩下的都不是功能缺口。

### 1.4 剩余项 Top 清单

核查时的 8 项 Top 缺口已在 M0–M3 关闭（真分页、字号变量化、AutoFit v2、分享 token、后端安全、CI/CD、数据可靠性、导出矩阵），M4 关闭了页面收尾与设计令牌两项，T5.1 关闭了投递管理，T5.3 关闭了 SEO 与示例页，T5.5 关闭了账号与合规，T5.6 关闭了可观测性，T5.7 关闭了 AI 改写。当前只剩：

1. **应用界面多语言** — 简历文档已支持中英双语，但界面文案（892 行模板文案、54 处 toast、18 条校验提示）仍是中文硬编码；见 T5.2 偏差 1，明确不做。
2. **人工验收项** — 打印页边距与预览在极端场景（超长单条、图片跨页）的一致性、375px 下的视觉走查，需要在真机/浏览器里过一遍，自动化测试覆盖不到；AI 改写还需要用**真实 Key** 在本地走一遍「接入 → 改写 → diff → 采纳」。
3. **外部服务的时效性** — 12 家厂商的接口地址与推荐模型名会随厂商升级而变（模型名可手改、也可「拉取列表」取实时清单，因此不影响可用性，但预设会逐渐过时）；各家服务条款对「内容是否用于训练」的规定也可能变化，`PrivacyView.vue` 第 7 节因此明确把这部分责任指向厂商条款。

**SEC-12 PBKDF2 实测结论**（Node 22 / Windows，`crypto.subtle.deriveBits`，SHA-256，256-bit）：

| 迭代次数 | 单次耗时 |
| :--- | :--- |
| 30,000 | 3.59 ms |
| 50,000 | 5.99 ms |
| 100,000 | 12.25 ms |

结论：**保持 100k 不变**。12ms 远低于 Cloudflare Workers 的 CPU 预算，且只发生在登录/注册/建分享链接这些低频路径上；降到 30k 会让离线爆破成本下降约 3 倍，收益不划算。

**顺带修复的真实缺陷**：

1. **`scripts/migrate.mjs` 在 Windows 下永远重跑全部迁移**：通过 shell 调 `npx wrangler ... --command=SELECT version FROM schema_migrations` 时，node 把参数按空格拼接，SQL 被拆成 4 个 token 并静默失败；`appliedVersions()` 拿不到任何版本，于是每次执行都从 `0001` 开始，第二次就会撞上 `duplicate column name`。已改为直接 `execFileSync(process.execPath, [node_modules/wrangler/bin/wrangler.js, ...])` + `--json` 解析，并区分「表不存在」与「真的查询失败」。

**与方案的偏差（有意为之）**：

1. **限流用 D1 表而不是 Cloudflare Rate Limiting**：后者是账号级配置，不随仓库走、本地与预览环境测不到、也无法写单测。一张小表换来「可测试 + 可迁移 + 可本地复现」，代价是每个限流请求多一次 D1 写入（低频路径，可接受）。
2. **限流失败时放行（fail-open）**：D1 抖动时宁可少挡一些脚本，也不要把正常用户全部锁在门外；异常会打日志便于告警。
3. **`POST /resumes` 也做体积校验**：方案只提到 PUT，但登录后的「本地草稿迁移」走的正是 POST，漏掉等于留了一个绕过口。
4. **正文损坏返回 50001 而不是空简历**：返回 `{}` 会让前端当作「用户清空了内容」并立刻回写覆盖，直接造成数据丢失。
5. **CI 里用 `PW_CHANNEL=bundled`**：GitHub runner 没有系统 Chrome，`playwright.config.ts` 默认走 `channel: 'chrome'` 会直接失败。

**顺带修复的真实缺陷**：

1. **登录会替所有人凭空建一份云端简历**：`migrateLocalDraft` 只判断 `resumeStore.isLocalDraft`，而 store 的初始 `id` 就是 `local-draft`，从 `/login` 直接登录的用户也会被当成「有待迁移的草稿」，创建出一份默认内容的简历。新增 `hasUnsavedLocalDraft`（`isLocalDraft` + 确实写过盘），并补 E2E 断言 `POST /api/resumes` 为 0。

3. **`Response` body 复用导致单测互相污染**：`useAuthForm.spec.ts` 里 `LOGIN_OK` 是模块级常量，`Response` 的 body 只能读一次，第二个用例起拿到空响应 → 登录被判定失败。改为每次 `loginOk()` 新建。

**与方案的偏差（有意为之）**：

1. **缩略图不挂真实模板组件**：一个列表可能有十几张卡片，每张都挂完整模板（含 `ResizeObserver` 与整套排版计算）会明显拖慢首屏。改为几个 div 的 CSS 版式图，表达「单栏/双栏/有无头像/有无强调色」四个真实差异，成本可忽略。
2. **完整度在服务端算**：列表接口本来就要查 `content`，让服务端顺带算一个 `{score, missing}` 比前端为每张卡片各发一次详情请求（N+1）便宜得多，且不把正文下发到列表页。
3. **`borderRadius` 保留现有取值而非按方案上移一档**：方案 1.3.1 的 xs–2xl 是「整体上移一档」的写法，直接套用会把全站圆角放大 4px（`rounded-xl` 从 12px 变 16px），属于视觉回归而非改进。这里显式声明与 Tailwind 默认一致的刻度，让 token 不依赖默认值，视觉不变。
4. **`shadow-sm` 不再进构建产物校验**：该档位可能只出现在 `hover:` 变体里，类名会被转义成 `.hover\:shadow-sm`，按 `.shadow-sm` 断言必然失败。守卫只校验基础档位 `.shadow-xs`。
5. **未做「预览默认 fit-width」**：`PreviewCanvas` 在移动端已有缩放与占位补偿（RENDER-06），强制 fit-width 会让「预览排版」Tab 在手机上把 A4 缩到不足 1/3 屏宽、文字完全不可读。保留手动缩放。
6. **未做「移动端 Header 全部收进更多菜单」**：编辑器 Header 的 `md:hidden` 菜单已覆盖全部次要操作，桌面态保留平铺入口（常用操作少一次点击）。只在 375px 下验证无横向滚动。
7. **`askChoice` 而不是扩展 `askConfirm`**：`askConfirm` 返回 `boolean` 且被 `remove()` 等调用方依赖，改成多选会波及所有调用点；新开一个 `useChoice` 保持两条路径语义清晰。

**与方案的偏差（有意为之）**：

1. **投递记录用独立页面 `/jobs`，不放在 Dashboard 顶部**：方案原文写「Dashboard 顶部到期提醒」。实际做成一等页面，是因为看板需要横向空间（五列），塞进工作台会把简历卡片流挤成次要内容；工作台只保留一个入口按钮。跟进提醒放在投递页顶部，与记录同屏，比跨页跳转更符合「想起来要跟进」的时机。
2. **`status` 存字符串而非枚举整数**：D1 里直接读得懂，加新状态（如「待二面」）不需要迁移，也不会出现「3 是什么」的困惑。代价是每行多几个字节。
3. **`ON DELETE SET NULL` 而非 `CASCADE`**：删掉一份简历不该让「我上个月投过这家」的记忆一起消失。投递记录是用户的求职历史，独立于简历文件存在。
4. **PATCH 只更新请求里出现的字段**：把缺失字段当 `null` 写入会清空用户没碰过的内容。字符串空串统一存 `NULL`，避免「有值但是空」的两种状态。
5. **日期用原生 `<input type="date">`**：投递记录只需要「哪一天」，不需要精确到分钟；自研日期选择器在手机上反而更难用。换算按本地时区做，避免 UTC 偏移导致日期差一天。
6. **未做拖拽换列**：看板移动状态走「更多操作 → 移到 xxx」菜单。原生 HTML5 DnD 在触屏上不可用，而自定义拖拽（`pointerdown` + 移动）在五列布局里容易与横向滚动冲突；点选在桌面与移动端都稳定，且可键盘操作。
7. **投递记录不进版本历史、不影响简历完整度**：两者语义不同（完整度衡量「简历写没写全」，投递是「投递行为」），混在一起会让完整度分数变成无法解释的复合指标。

**与方案的偏差（有意为之）**：

1. **不做邮件验证与密码重置**：两者都要邮件服务商凭据（Resend / Cloudflare Email Routing），仓库里没有也不该有，本地无法验证「发得出、收得到、链接不过期」这条链路。写一个不验证的假实现比不写更糟——用户会以为找回密码可用。因此「忘记密码」入口继续按 CUT-10 保持移除，注册也不加验证邮件。
2. **导出是单个 JSON，不是「JSON + 头像 ZIP」**：头像在 R2 里存的是 URL，不是用户上传的原始字节；为一个几乎没人打开的导出包再拉一遍 R2 并打 zip，收益不抵复杂度。JSON 里保留 `avatarUrl`，用户点开即可拿到图。
3. **改密后旧 token 不失效**：JWT 无状态，要做到「改密即踢下线」得给 `users` 加 token 版本号并在每次鉴权时比对，等于给所有请求加一次查库。收益（共享设备场景反而更糟）不抵成本，明确记录为取舍。
4. **注销用时间戳而非布尔标记**：`deletion_requested_at` 同时表达「是否申请」与「何时到期」，一个列就够；布尔标记还得再加一列到期时间，且两者可能不一致。
5. **冷静期内登录自动撤销，而不是登录后弹窗询问**：能登进来本身就说明用户后悔了。再让他在一个已经「半删除」的账号上做选择，是在为一个几乎不存在的场景增加摩擦。
6. **到期删除做双保险**：只靠登录时惰性删除，「注销后再没回来」的账号会永远留在库里——而这恰恰是最该删的一批。定时脚本与惰性删除共用同一套表顺序，避免两处逻辑漂移。
7. **删除不做事务**：D1 的批处理在部分表不存在时会整批失败。逐表删除 + 单表失败继续，保证「能删的都删了」，残留由下一次清理兜住。
8. **限流沿用登录档位**：改密与登录共用 10 次/分钟/IP。改密本身就需要旧密码，暴力尝试与登录暴力破解是同一类攻击，没必要单开一档。

**与方案的偏差（有意为之）**：

1. **不接 Sentry / GA，自建上报**：隐私政策写的是「不接入第三方统计、广告或用户画像服务，页面中没有第三方追踪脚本」。接一个 SDK 就把这句话变成假话，而自建只需要一张聚合表加一个接口。CSP 的 `connect-src 'self'` 本来也不允许外域请求。
2. **只存聚合，不存原始事件**：D1 免费额度每天 10 万次写入，单条事件表几天就写满。聚合表里没有 `user_id` / IP / 原始路径，即使泄露也不构成个人数据——这是「能观测」与「能免责」同时成立的最小集合。
3. **手写 Web Vitals，不引 `web-vitals`**：只需要三个值，一个依赖换 80 行代码不划算，也省掉一次「上报库自己是不是在偷偷发数据」的审计。INP 用「最长事件处理时长」近似，用途是「发现改版后交互变慢」，不追求与 Chrome 报告逐位一致。
4. **按路由名而不是路径统计**：`/editor/res_abc` 与 `/editor/res_def` 是同一个页面，按路径统计会把一个页面拆成上千行，报表直接失效；路由名是开发者定义的白名单，也天然挡住了「用户输入出现在 URL 里」的泄露风险。
5. **上报接口不做鉴权**：首页白屏比登录后保存失败更严重，而未登录用户没有 token。代价是任何人都能往聚合表里加计数，用「限流 + 事件名白名单 + 路径归一化」把损失压到「多几个数字」。
6. **任何参数问题都返回 204**：埋点客户端不该有错误分支。返回 4xx 会让前端多一套「上报失败怎么处理」的逻辑，而这套逻辑的唯一正确答案就是「忽略」。
7. **埋点请求不带 `Authorization`**：带上 token 意味着「埋点接口能拿到身份」，一旦日志或代理误配就是身份泄露。用 e2e 断言锁死这一条。
8. **告警是脚本 + 退出码，不是告警平台**：仓库里没有也不该有告警服务的凭据。退出码非 0 在 GitHub Actions 里就是红叉，在 cron + 任意通知脚本里就是「有情况」，两条路都通。
9. **开发期不上报**：HMR 会频繁抛「组件已卸载」之类的假错误，上报上去只会污染数据；`initTelemetry()` 默认关闭，由 `main.ts` 在 `import.meta.env.PROD` 下显式打开。

**与方案的偏差（有意为之）**：

1. **用「用户自带 Key + 厂商预设」，不用 Cloudflare Workers AI**（方案原文给了二选一）：Workers AI 的免费额度会随使用量消耗，而 AI 改写的调用频次完全由用户决定——陌生人可以把这个免费额度点到见底，等于给产品装了一个「谁都能拧开的水龙头」。自带 Key 则把成本、配额与合规责任都交还给用户，本站零边际成本，也不必设用量档位。
2. **请求经服务端转发，不让浏览器直连厂商**（方案未指定）：站点 CSP 是 `connect-src 'self'`，浏览器直连根本发不出去；而这条规则**同时**是「页面不会偷偷把你的简历发给第三方」的技术保证，不该为这个功能拆掉。且多数国内厂商不返回 CORS 头，直连本来也不可行。代价是 Key 会过一次服务端内存——用「不落库、不写日志、不校验登录 + 30 次/分限流」压到最小，并在**用户填 Key 的那个位置**（不是藏在隐私政策里）把这件事说明白。
3. **错误码刻意不含 401**：`src/utils/http.ts` 把 401 统一当作「登录态失效」并触发登出跳转。而「API Key 无效」是用户自己的 Key 有问题，与账号无关；若用 401 表达，一个设置错误会升级成「莫名其妙被踢下线」。因此 API Key 无效用 `50201`（HTTP 502）。
4. **`/api/ai/*` 的 5xx 不计入 `server.error.*` 告警**：那里的 502/504 说的是「用户自己配的模型服务商拒绝了这次请求」，不是本站故障。计进去的话，一个填错 Key 的用户就能让「5xx > 20 次/天」的阈值响一整晚。中间件里按路径豁免，日志级别降为 `warn`。
5. **提示词不放进 `shared/ai.ts`**：前后端共享层只放「两边都必须知道」的东西。提示词是服务端实现细节，前端既不需要知道，也不该让它出现在前端构建产物里。
6. **「不得编造事实」写死在系统提示词，且给出占位符出口**：简历是会被面试官逐条追问的东西，模型顺手补一个「提升 30%」就可能让人当场露馅。第 2 条约束要求缺数据时插入 `[请补充具体数据]`——否则模型只有「编一个」和「什么都不写」两个选择：前者有害，后者等于没改写。
7. **`redirect: 'manual'`**：自定义 base URL 已挡掉内网地址，但若放行重定向，对方仍可用一个公网域名 302 到 `169.254.169.254` 绕过校验。3xx 一律判失败。
8. **客户端超时（60s）刻意大于服务端上游超时（45s）**：反过来的话先超时的是浏览器，服务端辛苦翻译出来的错误文案永远送不到用户眼前，用户只能看到一个没有原因的失败。
9. **自定义厂商只允许 https**：明文 http 会把用户的 API Key 暴露给链路上任何一环。代价是自建的内网服务（内网 Ollama、公司网关）用不了——这是有意的取舍，那类服务本来就只在你自己的机器上，我们要防的是「别让我们变成别人的跳板」。
10. **不做流式输出**：流式会让「必须人工确认才写回」这条约束变复杂，而改写目标是「一段 200 字的经历」，等 5 秒用户完全可以接受；换来的是结果可控与 diff 可直接计算。
11. **模型名不写死**：厂商改名频繁（`glm-4-plus` → `glm-5`），因此模型名始终可手改，另有「拉取列表」从厂商取实时清单。预设的准确性只影响首次体验，不影响功能可用性。

## 5. 风险与应对

| 风险 | 影响 | 应对 |
| :--- | :--- | :--- |
| 真分页引擎导致输入卡顿 | 编辑器体验倒退 | rAF + 150ms 节流；仅页数变化时重建 DOM；`data-block-id` 保 key；必要时虚拟化长文档 |
| 模板重构导致老简历外观突变 | 用户投诉 | `templateVersion` 冻结旧版；灰度；提供「恢复旧版」 |
| IDB 迁移丢失草稿 | 用户数据损坏 | 迁移前导出备份；双写 7 天；迁移脚本幂等 |
| `safeUrl` 收紧导致既有外链失效 | 用户困惑 | 非法协议降级为纯文本 + 提示，不删除数据 |
| 限流误伤正常用户 | 登录失败 | 阈值可配；白名单；监控 5xx 与 429 比例 |
| DOCX/二维码引入增大包体 | 首屏变慢 | 已落实：`docx` 打成独立异步 chunk（gzip 110KB），仅在选择 Word 导出时加载；首屏入口包不受影响 |
| 云端 PDF 已下线，用户仍期待「一键下载」 | 预期落差 | 已落实：导出弹窗明确「将打开打印对话框，选择另存为 PDF」；按钮文案为「打开打印」 |
| 合规文案与实现不一致（写了没做的事） | 法律与信任风险 | 隐私政策只写代码中可验证的事实（表结构见 `docs/schema.sql`、逻辑见 `functions/`）；T5.5 后注销、导出、改密均已实现，文案随之改为事实描述；邮件验证/密码重置仍未做，文案中不出现 |
| 注销账号的到期删除被漏跑 | 用户数据超期留存，违反承诺 | 双保险：登录时惰性删除（返回 `40105`）+ `scripts/purge-accounts.mjs` 定时清理；清理脚本 `--dry-run` 可先看会删什么 |
| AI 改写把服务器变成他人跳板（SSRF） | 用本站读内网服务或云元数据 | 预设厂商只认 `shared/ai.ts` 白名单并忽略客户端地址；自定义仅 https、禁凭证/查询串/锚点、拦截私有与保留网段；上游请求 `redirect: 'manual'`，3xx 一律失败 |
| AI 改写的 Key 经服务端内存 | 密钥泄露风险 | 不落库、不写日志、不校验登录、30 次/分/IP；`rememberKey` 关时不写浏览器本地；服务端只记 `provider/style/target/字数区间`。已在真实链路上验证日志无 Key 与正文 |
| 模型编造经历写进简历 | 用户在面试中当场露馅 | 系统提示词硬约束「不得编造事实」+ 缺数据时用 `[请补充具体数据]` 占位；结果**必须过 diff 并由用户点「采纳」**才写回 |
| 用户配错 Key / 模型名导致大量 502，污染 5xx 告警 | 真故障被淹没 | `/api/ai/*` 的 5xx 记 `warn` 且不写 `server.error.*`；同时记 `ai.rewrite.fail`，它才是「预设是否过期」的信号 |
| 厂商接口地址或推荐模型名过时 | 首次体验失败 | 模型名始终可手改 + 「拉取列表」取实时清单（预设只负责「首次能跑起来」）；失败文案附服务商原话，用户可直接据此搜索 |
